## LinkedIn

OpenReadiness is open for contributions.

We are building an open-source prototype for operational readiness coordination
before and during complex crises. The current Python scaffold combines an
OR-Tools capacity allocator, a six-state action engine with in-memory audit
records, and a runnable synthetic replay.

We welcome Python developers, optimization specialists, and preparedness
practitioners. Three beginner-friendly tasks cover solver tests, action-transition
tests, and a data dictionary. Evidence freshness, input validation, and selectable
synthetic scenarios are implemented and welcome further review. Domain feedback
and documentation count too.

This is an early prototype: federated evidence verification and production
operations remain future work.

## Python and optimization communities

Looking for a small open-source contribution? OpenReadiness has scoped tasks for
Python/Pydantic tests, OR-Tools allocation edge cases, schema validation, and
synthetic replay scenarios. The project separates deterministic allocation from
any future unstructured-input agents. It uses pytest and CI on Python 3.12/3.13,
plus a container replay check.

Starter tasks: https://github.com/PAG-droid/open-readiness-tower/contribute
Demo and current limitations: https://github.com/PAG-droid/open-readiness-tower/blob/main/docs/demo.md

## Preparedness and public-health communities

What should operational readiness software prove before it calls a resource
available? OpenReadiness is an early open-source prototype exploring capacity
conflicts and accountable action workflows with synthetic data.

We would value feedback on realistic, nonconfidential disruption scenarios,
evidence freshness, and the difference between a claimed resource and a verified
commitment. Coding is optional; a concrete scenario or documentation correction
is useful. The prototype does not yet verify real-world readiness.

Discuss ideas: https://github.com/PAG-droid/open-readiness-tower/discussions/categories/ideas
